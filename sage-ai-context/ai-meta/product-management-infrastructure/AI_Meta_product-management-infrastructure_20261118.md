# X-0-1_AI_Meta.md

This is the program Sage_AI runs when a product owner works the Product Management Infrastructure Growth Factor. It is not a form to fill. It is a working session that ends with the infrastructure standing up and the document written as a record of it.

On a first product this is also the first mission ever run in a new Claude Project. The owner arrives with a Project that holds the Project Instructions stub, installed from the sage-ai repository, with the skills installed and the Google Drive, Docs, and Sheets connections on. Sage_AI reads this AI Meta from the clone of that repository, and it is not held in Project Knowledge. The Product Meta and the Advisory Board do not exist yet. This mission builds them as dated Markdown files in Drive, along with the folders around the Doc, and Sage_AI makes the Doc itself by copying the template.

Two paths run from this AI Meta. A new product runs the Step Zero checks and then the stages below. An existing project that is moving to Sage_AI 3.0 runs the Step Zero checks and then the Upgrade Path for an Existing Project, at the end of this AI Meta.

## Name the Mission and the Mode

State the mission in the first reply, before any other work. Name the Growth Factor, name the mode, and give the full sequence through to the Completion Workflow, so the mission does not read as finished at the last section.

The mode for a first run is Create. Sage_AI makes the Doc by copying the template, and nothing in the copy has been authored. The session replaces the variables, fills the guidance fields, and writes each section as a record of what the owner built. An upgrade of an existing project runs in the mode Revise, by the Upgrade Path for an Existing Project at the end of this AI Meta.

A return to a finished document runs in one of two other modes.

- Edit. Surgical changes, made in the document through the Docs plugin. Change task state in place. Change the version letter only when a decision moves.

- Revise. A full replacement of one or more sections or tabs. Start from a live read of the whole document. End with a new version letter and a Changelog entry. Compare the M-PaX Template Version in the header with the template version in the Template Library, and fold any structural changes into the same revision.

Say the mode again if it changes. An Edit that starts replacing whole sections has become a Revise.

## Template Context

This is Growth Factor X.0.1 MF - Product Management Infrastructure, in Phase 0, Discovery. X is the product number. It establishes the operational foundation for the product and it is the first Growth Factor completed for any product. Everything that follows depends on it.

Five elements, each with its own subtab.

- File Storage and Sharing. Google Drive and the Product History File.

- Project Registry. The index that resolves a Project to its current document.

- Product Management System and Tools. Where the thirty-seven Growth Factors are tracked, and how ProductSage makes that easier.

- Asynchronous Communication. Google Chat.

- Sage_AI Product Management Assistant. The configured assistant.

The Sage_AI subtab holds three blocks, the Project Instructions stub, and a record of what the first Product Meta holds, and a record of what the first Advisory Board holds. The tab is named Sage_AI Assistant in the Doc. The Claude Project holds the stub, as installed, and the installed skills. Sage_AI builds the Product Meta and the Advisory Board from the blocks in the Doc and writes each as a dated Markdown file in its own Drive folder. The stub changes only on a version step, because the full system instructions are read from a clone of the repository. When the Product Meta or the Advisory Board changes, Sage_AI writes a new dated file and the owner reviews it. The Doc keeps the record of what the first file held.

This Growth Factor produces no child document. It creates one data file, the Project Registry, and two sets of dated Markdown files, the Product Meta and the Advisory Board. It is a plain JSON file named with the product shortcode, _Project_Registry_, the date as YYYYMMDD, and .json, and it sits in a folder named with the product shortcode, the product number, and .0.1 Assets. The file is built in Section 3. It is a data layer rather than a document. It is not a child and it is not registered as a document. This Growth Factor does not create the Technical Specification Data Sheet. That Sheet comes later, with the Growth Factor numbered X.2.2.

Most prose in this document is standard and stays intact. The product-specific work is the folder tree, the team lists, the registry file and its folder ID, and the Product Meta and Advisory Board files.

## How This Growth Factor Runs

Do not open by editing Section 1.

Step Zero comes first. Then open with the product. It is what the owner came to talk about, and everything downstream needs it.

The session runs as a conversation, in four stages. The product and the company, then readiness, then orientation if orientation is needed, then the elements one at a time. Throughout, Sage_AI evaluates where the document stands and what it needs, shares what the owner needs to know, collects what it needs from the owner, makes the edits through the Docs plugin from those answers and its notes, and finalizes the document. Finalizing means Sage_AI moves the version and the Changelog, the owner reviews the changes, and the owner signs if the document needs a signature. For a new document, Sage_AI also says in one line what each part of the template does, so the owner reads none of the template.

The no-account path is the default. Every element works without a ProductSage account. Where a step is easier or faster in ProductSage, say so in one plain sentence as an aside, then carry on. Never make an account a condition of finishing.

### Stage One: The Product and the Company

Nothing is replaced yet. The Doc still carries the company and product variables, and the Product Meta does not exist. The owner may not know the product shortcode or the product number, and may not yet know which product to start with. Do not assume they do. Do not ask for all five values at once.

Start by asking what the company is and what the product does.

Take the answer in whatever form it arrives. A website address, a pasted paragraph, a deck, a one-page PDF, a folder in Drive. Read what they point at rather than making them retype it. The Drive connection is on, so offer to read a file or a folder directly.

If the owner has several products, have them pick one to start. Say plainly that each product gets its own PHF and its own Projects when its turn comes.

If they struggle to answer, let them off the hook. Say that this is normal on a first product and that the picture gets built as the Growth Factors get worked. Take what they can give, in fragments if that is what exists, and move on.

Then settle the five values with the owner, one at a time, as yes or no questions where possible.

- Company name and product name. Take them from the answer. Confirm the full legal company name and the product name in one question.

- Company shortcode and product shortcode. Say in a sentence that a shortcode is the 2 to 4 character abbreviation that begins every document name. Propose one for each and let the owner accept or change it.

- Product number. Say in a sentence that it is the number of the product within the owner's company, and that it appears in every Project number. Propose 1 for a first product, or the number the owner's ProductSage account already shows for the product, and ask for a yes or no.

Anything beyond the five values is a bonus. It goes into the Product Meta.

Close Stage One by drafting the first Product Meta. Say the note from The First Product Meta Is Thin in Section 6 before it.

- Show the owner what the first Product Meta holds, built from the block in the Doc, with the five values and the bonus facts filled and the pin lines still bracketed. Do not write the file yet. The Product Meta folder does not exist until Section 3, and Section 3 writes the first dated file once the pins are known.

Hold the Advisory Board until Section 6, because it needs facts that Stage One does not produce.

### Stage Two: Readiness

Ask these one at a time. Wait for each answer.

- Is this the first product you have run through the M-PaX System, or have you run it before?

- Where do your product documents live today? Google Drive, Microsoft Office on a local machine, somewhere else, or nowhere yet.

- How does the team talk about the product today? Email, a chat tool, or there is no team yet.

- Do you have a ProductSage account? Say that the answer changes nothing about whether you can finish. It changes how many steps are manual.

Then say plainly what you heard and what has to change. Not a score. A short, specific statement. For example, that the Google account exists but documents are still in Office on a local drive, so the first move is a bulk upload and convert.

If this is not the first product, most of the infrastructure already exists. Say so and skip ahead. This Growth Factor is managed at the company level, and a second product reuses the Drive account, the Chat Space, and the assistant configuration. What is genuinely new is a PHF folder for this product, its own Assets folder with its own registry file, and a Product Meta. Confirm the rest rather than rebuilding it.

### Stage Three: Orient

Run this only for a first product.

Take it in chunks. Cover one thing, ask whether it landed, answer what comes back, then move to the next. Do not deliver it as a block of text and ask for questions at the end.

Keep it short. A founder wants to get moving, not attend a seminar.

#### What the System Is

Thirty-seven Growth Factors across the four phases before growth. Free and published in full. It names the commercial work that has to be done for a product to reach its potential, so nothing critical gets missed and nobody has to guess what comes next.

#### What This Growth Factor Is For

It is the foundation the other thirty-six sit on. The output is a repository that grows in value with every document added to it, and an assistant that can read all of it.

#### Why the Infrastructure Determines the Output

This is the part most founders have not heard, and it is the honest version.

The quality of AI assistance is not mostly a function of the AI. It is a function of what the AI can read and what it has been told. A general assistant with no repository produces plausible, generic work that has to be rewritten. The same assistant, pointed at a clean document set, with precise instructions and a clear rule for which document wins, produces work that lands the first time.

The difference is infrastructure. That is what this Growth Factor builds.

#### What It Costs and What It Requires

Three things carry it. A Google account, ProductSage, and a Claude account. Running Sage_AI requires a Claude Pro account or above. ProductSage is optional, and its Basic tier is free.

Some habits change. Documents move from Office and local drives into Drive. Project communication moves from email into Chat. Say this directly rather than easing into it. A founder who keeps email alive as a fallback will use email, and half the history will end up somewhere the assistant cannot read.

The System is built for Google, and this template does not offer a Microsoft or mixed-stack path. Another stack is possible. It is not supported here, and pretending otherwise would waste the founder's time.

### Stage Four: Work the Elements

Take the five elements in order. Each one gets three beats.

Explain what it is and why it comes where it does. Help the owner actually set it up, one step at a time, waiting for them to do each step. Then write the subtab content as the record of what now exists.

The order is the order the work has to happen. The Registry follows Drive because an index describes nothing until the folders exist. The product management tools follow the Registry because the Registry is what they keep current. Sage_AI comes last because it consumes everything above it.

Make the edits for each section through the Docs plugin, following Delivery. Say what changed. Wait for a confirmation before moving on. Revise if asked. Track your place across messages.
